# Article editor (Phase 1, 2 and the HTML block) and form editor (Phase 3)

Source of the article block editor used by `public/edizon/article.php`.

- `src/main.js` editor shell (dock, canvas, all block types including cards and table), `src/rte.js` rich text (Tiptap), `src/editor.css` editor styles, `src/shared.css` fonts and `fs-/ff-/ta-` classes shared with the public page.
- `npm install` once, then `npm run build`. It writes `public/edizon/assets/article-editor.js` and `.css`, copies the new fonts to `public/fonts/`, and rewrites the block between `/* article-rich:start */` and `/* article-rich:end */` in `public/articles/articles.css`.
- `npm run harness` serves a copy of the article page with the real PHP validation and renderer but no database or login (needs `php` on the PATH; XAMPP has one): http://127.0.0.1:8099/edizon/article.php
- `npm test` (second window, needs `npm i -D playwright && npx playwright install chromium`) runs the browser checks. `npm run test:php` runs the PHP checks without a server.
- The widths of the article page (text column, wide blocks, page frame, gutter) are set in ONE file, `public/articles/template-vars.css`. The public pages and this editor both load it, so the editor's Desktop, Tablet and HP views follow it. Change widths there only; the harness copies it too.
- After changing a panel asset, raise `PANEL_VERSION` in `public/edizon/lib/bootstrap.php`.
- `public/fonts/` already holds Plus Jakarta Sans, Lilita One and Kite One (they come with the site); the harness needs that folder.
- HTML block (Admin only): own HTML/CSS/JS shown in a sandboxed iframe whose document comes from a real page with its own security policy (`public/articles/frame.php` for published articles, `public/edizon/article-frame.php` for the panel). Never inlined in the article page. Upload both files together with `lib/articles.php`. The harness serves the real frame pages plus `articles/public-test.php`, a stand-in public article page.
- HTML block limits: 300,000 letters of code; height Otomatis / Pendek / Sedang / Tinggi / Sangat tinggi / "Setinggi layar" (100vh; for app-style pages that fill the screen). With JavaScript on, the code gets a replacement `localStorage` / `sessionStorage` (the frame has no real storage): `localStorage` is handed in through the frame's window name before it loads (`articles.js` clones the iframe with `name="enls:{json}"` because a name set on an already attached iframe is lost) and changes are posted back (`{enFrame:2}`) and kept in the visitor's browser under `enhf:<article>:<block>` (max 200 keys / 200,000 letters per block). `sessionStorage` is memory only. In the panel preview nothing is stored. Browser-only APIs of other apps (for example `window.claude` of Claude artifacts) do not exist in the frame.
- Article option "Pakai lebar layar penuh" (article settings, stored in the SEO JSON as `layout: "full"`, no database change): the content blocks use the whole browser width instead of the template width; the title, tags and cover keep the template width. Public CSS is the `.art-full` block at the end of `public/articles/articles.css` (outside the generated block). The editor canvas follows the option on the Desktop view.
- Previews of HTML blocks are reloaded after every save (an iframe that is re-attached reloads; an Admin's unsaved preview is POSTed, so it would stay blank otherwise).
- The harness copies the site files when it starts: restart it (`npm run harness`) after changing a PHP, JS or CSS file of the site, otherwise the tests run against the old copy.
- Tests: 238 browser checks and 133 PHP checks (articles).

## Form editor (Phase 3)

- `src/form-main.js` + `src/form-editor.css` build into `public/edizon/assets/form-editor.js` / `.css` (SortableJS only, about 21 KB gzipped); `npm run build` does both editors. `public/edizon/form.php` loads them and `assets/form-builder.js` (basic data, texts, drafts switch) mounts the editor under "Susunan formulir".
- Model: `cfg.steps[]` = `{id, name, items[]}` with items `field {key}`, `row {id, keys[2-3]}`, `h {text, textAdult, level 2|3}`, `text {text, textAdult}`, `hr`. `cfg.fields[]` stays the flat list in display order (steps, then left to right), so conditional fields ("tampil jika" must point at a field earlier in that order), Zapier payloads and submissions are unchanged. A form saved before steps existed shows as one step. Limits: 8 steps, 30 fields, 60 items per step, 40 layout blocks, 3 fields per row (only text, email, phone, date, dropdown).
- Server: `lib/forms.php` (`form_check_steps`, `form_steps_sync`, `form_public_def`, `form_rev`, `validate_form_def`); the old editor payload without `steps` still saves (one step).
- Public: `public/forms/popup.js` + `forms.css` (steps with Back/Next and per-step checks, the last step checks every step again, steps whose fields are all hidden by "tampil jika" are skipped, rows stack on phones). Drafts (`cfg.drafts`, default on): visitor's `localStorage` key `enf:draft:<slug>`, text/choice/date values only (never consent boxes or files), current step, expires 3 days after the last change, dropped when the field structure changes (`rev`), deleted after sending (also on the WhatsApp fallback), expired or broken drafts of any form are swept on page load; blocked storage = no drafts and no notice. The form says that answers are kept on the device. Review with your privacy adviser (UU PDP).
- Zapier: while "Kunci di Zapier" is empty the column name follows the label; renaming a saved field warns and offers "Kunci nama lama".
- `npm run harness:forms` serves http://127.0.0.1:8098 (real `forms.php`, `form.php`, `form-preview.php`, `public/forms/*.php`; SQLite file instead of MySQL; static files are symlinked, PHP pages are copied at start so restart after changing a .php file). `npm run test:forms` runs 62 public-form checks (`test/form-run.js`) and 61 editor checks (`test/form-editor-run.js`); `npm run test:php` also runs 54 form PHP checks (`test/php/forms.php`).
- Version numbers raised: `PANEL_VERSION` 2.2, `$v = '9'` in `public/articles/_render.php`.

## Phase 5 (undo / redo, outline, revisions, block templates)

All of it is in the shared editor (`src/main.js`, `src/editor.css`), so articles, pop-ups and quiz result pages get it together. No setting needs to be turned on.

- Undo / redo: Ctrl+Z, Ctrl+Y (also Ctrl+Shift+Z) and the two buttons in the dock bar. Everything in the editor is covered (typing, settings, add, move, delete, columns); the history is kept in the browser tab only, at most 100 steps, and starts again when a page is loaded or another quiz result is opened. After Save the server's cleaned copy becomes one more step (`setBlocks(list, {keep: true})`).
- Outline: the "Struktur" button lists every block (columns nested) to select, move, duplicate and delete. Alt + arrows on the block handle or an outline row move a block; Left / Right move it between the columns of a Columns block.
- Revisions (articles, pop-ups, quizzes): every save keeps the form data of that moment (last 30 per item, table `item_revisions`, created by itself). The card "Riwayat versi" under the editor lists them, opens a preview (`article-preview.php`, `popup-preview.php`, `quiz-preview.php` with `&rev=N`) and loads an old version into the editor as an unsaved change; it becomes the live version only when Save is clicked. Server: `lib/revisions.php`, endpoint `revisions.php`, `assets/revisions.js`.
- Block templates: the "Templat" button saves the chosen block (with the blocks inside a Columns block) or the whole page, and inserts a saved one below the chosen block (or at the end). One shared list for the three editors (table `block_templates`, created by itself, 200 templates, 400 KB each, unique names). Saving runs the same validators as saving the page, so unfinished blocks (no image yet, button without a target, empty text) are left out and reported; ids are removed and made new on insert. Blocks the open editor cannot hold (Score in a pop-up, Form in an article) are skipped and reported. HTML blocks can only be saved and inserted by an Admin. Rename and delete: the author or an Admin. Server: `lib/templates.php`, endpoint `templates.php`; the pages pass `templatesUrl: 'templates.php'`.
- Tests: `npm run test:history` (63, article harness), `node test/revisions-run.js` (50, needs both harnesses with EMPTY databases: restart them first, because every run saves), `npm run test:templates` (57, pop harness), `npm run test:php` (also `test/php/revisions.php` 37 and `test/php/templates.php` 40).
- Version number raised: `PANEL_VERSION` 2.5 (the public `$v` in `public/articles/_render.php` stays at 12: no public file changed).
